## 2026-08-12 — UI hang on detail-drawer open after connecting to large cluster

- **Root cause**: All ~30 K8s informers (`internal/kube/informers.go:58`) share one 30s `SharedInformerFactory` resync period, so they periodically fire near-simultaneous emit bursts. Each `emitXxx(namespace)` handler did a redundant second `ListXxx(lister, namespace)` (full relist + DTO reconversion) after already listing cluster-wide, and `emitPodsWithMetrics` additionally blocked the whole emit on a synchronous metrics-server HTTP call (`metricsFetchTimeout = 3s`, `internal/app/app.go:25`) before emitting anything. On the frontend, every pushed Wails event applied `setState` synchronously with no priority, and `DeploymentDetailDrawer`'s tab derivations re-filtered/re-sorted on every unrelated array replacement — so a resync-boundary collision with drawer-open produced a burst of large, unprioritized, non-memoized re-renders that blocked the main thread (unclickable UI for several seconds).
- **Fix applied** (no CRITICAL/HIGH from Phase 5 review): namespace-scoped emit branches in `internal/app/{pod,deployment,daemonset,replicaset,statefulset}.go` now filter the already-fetched cluster-wide slice in memory instead of re-listing; `pod.go`'s `emitPodsWithMetrics` emits pods immediately and fetches/applies metrics in a background goroutine (reusing the captured `allPods` slice, not re-listing) before re-emitting. Frontend `use{Pods,Deployments,DaemonSets,ReplicaSets,StatefulSets}UpdateEvents.ts` wrap their event-driven `setState` in React 19 `startTransition` so background pushes are deprioritized below user interactions like clicks. `DeploymentDetailDrawer.tsx`'s `DeploymentOverviewTab`/`DeploymentPodsTab` derivations are now `useMemo`'d.
- **MEDIUM** ✅ — Jittering/staggering the shared 30s resync period across the ~33 registered informers so they don't fire in lockstep. Fixed: `internal/kube/informers.go`'s informer-start loop now delays `go inf.Run(ch)` by `time.Duration(i) * 300ms` per informer's index in `informerList` (max spread ~9.6s across 33 resources), started in a goroutine that also respects early stop-channel closure. Rejected `client-go`'s `informers.WithCustomResyncConfig(map[v1.Object]time.Duration)` as the mechanism — it requires constructing zero-value pointers of all 33 K8s API types across ~12 extra package imports for exact type/version matching (e.g. HPA must be `autoscalingv2`, not `v1`), too verbose/risky versus the staggered-start approach, which achieves the same lockstep-avoidance since the resync ticker starts on `Run()` and persists for the informer's lifetime. Required updating `internal/app/informer_sync_gating_edge_test.go`'s `TestGetSyncedChanMultipleResourcesInSequence` fixed 1s timeout to 5s since it waits on `"configmaps"` (index 7, ~2.1s stagger delay) — same fixed-timeout pattern would need revisiting if `informerList`'s ordering changes materially.
- **MEDIUM** ❌ reverted — Pods/Deployments tables render every row via `.map()` with no virtualization. Piloted `@tanstack/react-virtual`'s `useVirtualizer` on `PodsView.tsx` only (user chose "pilot on Pods view only" over rolling out to all 7 workload views). Two real bugs were found and fixed along the way (both still valid, independent of the revert):
  - **`min-h-0` gap**: a `flex-1` scroll-wrapper's default `min-height: auto` lets it grow to fit content unless paired with `min-h-0` — canonical Tailwind recipe for scrollable flex children (`flex-1 min-h-0 overflow-y-auto`).
  - **Dead CSS selector** (kept, see below): `frontend/src/style.css` had `#app { height: 100vh }` but the app mounts into `<div id="root">` — `#app` matched no element, so no ancestor in the whole app had a genuinely bounded height. Fixed by renaming to `#root`; this is an app-wide layout bug, unrelated to virtualization, and was **not reverted**.
  - Despite both fixes, the user still reported no change live (`document.querySelectorAll('[data-index]').length` still ≈ total pod count) and asked to revert `useVirtualizer` entirely, suspecting a `@tanstack/react-virtual` incompatibility (possibly with the Wails/WebKit webview — not confirmed). **Reverted**: `PodsView.tsx`, `frontend/package.json`, `pnpm-lock.yaml` restored to pre-pilot state via `git checkout`; `@tanstack/react-virtual` removed from dependencies.
  - **Do not re-attempt `@tanstack/react-virtual` in this codebase without first confirming in the live `wails dev` webview that `useVirtualizer`'s ResizeObserver-based measurement actually fires** (e.g. log `rowVirtualizer.getVirtualItems().length` and the scroll element's `clientHeight`/`scrollHeight` directly) — two plausible, unverified root causes remain: (a) the Wails webview's ResizeObserver/IntersectionObserver support behaving differently than Chrome, or (b) some other unidentified layout issue beyond the two already fixed. If revisited, treat this as needing local reproduction in the actual target webview before trusting static CSS reasoning again.
- **Known trade-off, accepted**: the async metrics goroutine in `emitPodsWithMetrics` isn't synchronized against later emit calls — if two emits fire close together, an older in-flight metrics goroutine could theoretically re-emit a slightly stale pod snapshot after a newer emit. Reviewed and accepted as a minor, self-correcting staleness window (next resync/query overwrites it) traded for UI responsiveness — do not "fix" this with added synchronization unless it's shown to cause a real user-visible issue.
